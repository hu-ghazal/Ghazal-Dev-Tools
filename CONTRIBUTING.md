# Contributing

Thank you for helping. This page says how to send a change and on what terms it is accepted.

## How to send a change

1. **Fork** the repository and make your change on a branch of your fork.
2. **Test it.** Add or update the tool's tests and run them; say in the pull request what you ran.
3. **Open a pull request** that says what it changes and why. One tool and one purpose per pull request.
4. The maintainer reviews it. A change is merged only after that review.

Contributors do not get write access to this repository; every change arrives through a pull request.

## Commit identity

Your name and email appear in the history of a public repository and cannot be removed later. We recommend your GitHub
no-reply address (GitHub, Settings, Emails, "Keep my email addresses private"), which looks like
`12345+your-name@users.noreply.github.com`. Set it for this repository with:

```bash
git config user.email "12345+your-name@users.noreply.github.com"
```

## Keep it clean

- No keys, tokens, passwords, personal paths or machine-specific settings in files, commit messages or file names.
  Secret scanning and push protection are on and block a push that holds a known secret.
- Keep each tool self-contained: it must work on anyone's setup, with paths relative to the tool.
- Security problems are reported privately, never in an issue or pull request: see [SECURITY.md](SECURITY.md).
